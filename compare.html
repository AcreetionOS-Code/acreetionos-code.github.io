Why AcreetionOS?

We built AcreetionOS because we believe Linux should be for everyone — not just tech elites. Here's how we compare to the other guys.

Our Position

We're here so people don't get screwed by Microsoft, Google, and Apple. Big Tech has spent decades locking users into ecosystems that prioritize shareholder value over user freedom. AcreetionOS is our middle finger to that — an Arch Linux foundation that actually works for normal people, with a graphical installer, Cinnamon desktop, and curated stability. No telemetry, no accounts required, no planned obsolescence. Just a computer that does what you tell it to do.

Arch Linux

The Foundation
Technical excellence, but not for everyone
Arch is the most powerful Linux distribution available. The rolling model, AUR, and Arch Wiki are unmatched. But Arch makes no compromises for accessibility — you're expected to read the Wiki and configure everything yourself. That's fine for power users, but it's a non-starter for people who just want a working computer.
  • Maximum flexibility and control
  • Arch Wiki is the gold standard
  • True rolling release
  • Manual install only — no graphical installer
  • Requires significant Linux knowledge day-to-day
  • Bleeding edge can break — you fix it
AcreetionOS is Arch that just works. Same rolling base, same official repos, plus our curated repo. But with a graphical installer, pre-configured Cinnamon desktop, and stability testing. You get Arch power — none of the hassle.

Ubuntu

Corporate Linux
Canonical's walled garden
Ubuntu made Linux accessible to millions, and for that it deserves respect. But Canonical has been pushing Snap packages aggressively — proprietary backends, forced updates, and slower performance than native packages. Ubuntu also uses point releases, meaning you're stuck on older packages until the next version. And every LTS release eventually goes end-of-life, forcing upgrades.
  • Good hardware support
  • Large community
  • Canonical pushes Snap whether you want it or not
  • Point releases — outdated packages quickly
  • Forced upgrade cycles every few years
  • Growing corporate influence over direction
AcreetionOS respects your choices. No Snap, no Flatpak pushed on you. Native packages and AUR. Rolling updates so you're never stuck on old software. No corporate overlord deciding what's best for your system.

Linux Mint

Respected Competitor
Great Cinnamon distro, different base
Linux Mint is excellent — the team behind Cinnamon, great user experience, rock-solid stability. But it's built on Ubuntu (ultimately Debian), which means point releases. Every version upgrade is a gamble, and packages get stale between releases. You also inherit all of Ubuntu's Snap baggage.
  • Best Cinnamon implementation in the Debian world
  • Polished and beginner-friendly
  • Ubuntu/Debian base — point release model
  • Version upgrades can break things
  • AUR not available
  • Older packages between releases
AcreetionOS gives you Cinnamon on Arch. Same great desktop, but with rolling updates, AUR access, and no version upgrades. We believe Cinnamon belongs on a rolling base — and we built it.

Fedora

Innovation First
RPM/DNF ecosystem
Fedora pushes Linux forward with cutting-edge features. But it uses RPM/DNF instead of pacman, which many find less intuitive. Fedora's release cycle (6 months) means you're constantly facing upgrade decisions, and each release is only supported for 13 months — forcing you to stay current whether you want to or not.
  • Up-to-date software
  • Strong security practices
  • RPM/DNF — different ecosystem from Arch/Debian
  • 13-month support window — frequent upgrades required
  • Not truly rolling — periodic releases
  • Smaller third-party package selection
AcreetionOS rolls forever. No version upgrades. No end-of-life deadlines. One install, continuous updates, pacman package management, and access to the AUR's massive package selection.

Manjaro

Arch Derivative Not Recommended
Arch-based, but compromised
Manjaro deserves credit for making Arch accessible to many users. However, their approach has real problems. They hold packages back from Arch repos for "stability" — but then don't have the testing infrastructure to actually validate those delays. This has caused multiple certificate expiration incidents and broken updates that wouldn't have happened on stock Arch. Their AUR handling encourages unsafe practices, and their governance has been controversial.
  • User-friendly tools (MHWD, pamac)
  • Holds packages back without proper testing infrastructure
  • Multiple security incidents from delayed updates
  • AUR handling that bypasses safety checks
  • Governance and transparency concerns
  • Larger, less focused — tries to be everything to everyone
AcreetionOS stays close to upstream Arch. We don't hold packages back — we trust Arch's rolling model and add our own curated repo for AcreetionOS-specific packages. Our focus is tighter: one flagship desktop, one vision. Not trying to be the "Ubuntu of the Arch world."
